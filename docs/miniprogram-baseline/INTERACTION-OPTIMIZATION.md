# 双端滑轨与封面预览优化

日期：2026-10-22。分支：`feature/wechat-miniprogram`。

## 修改

- 视频生成和照片 + 视频共用一条起止进度条；两个手柄不能交叉，拖动保留抓取偏移，点击轨道移动最近的端点。支持多指隔离、异步测量、触摸取消和组件销毁。
- 封面拖动只更新时刻并调用原生播放器 seek，60 ms 合并连续请求，松手提交最终位置。导入、拖动和松手不再启动 VideoDecoder 或 JPEG 导出，点击生成时才提取最终封面。
- 修改范围/封面后清理失效结果；未改变的高清封面可复用。照片模式保留所选照片，无须视频解码。
- 暂停、切换素材、隐藏和卸载时取消过期预览任务。修复 loadedmetadata 早于 setData 回调时，就绪状态被覆盖而无法提交定位的问题。

- 生成时只提取最终封面一次；相同时刻重试复用封面；解码失败释放忙碌状态。测试同时覆盖手动照片、范围约束、重复点击、旧输出清理及两种元数据/渲染回调顺序。
- 共享核心 9 模块一致性、JS 语法、WXML/WXSS 编译、`git diff --check` 通过。
- Web：16 项通过，3 项因既有外部样本缺失跳过；生产构建通过，保留既有 HEIC 包体积提示。

## 开发者工具观察与边界

开发者工具 Stable 2.02.2608070 已实际导入本机合成的 6 秒 MP4，验证单轨双手柄及起止标签变化。新增组件后，旧增量编译缓存曾导致 `range.js is not defined` 和白屏；清理项目编译缓存后重新编译，组件可正常加载。

本机工具提示 `getVideoInfo:fail 音视频处理需要使用 ffmpeg`，应用使用选择器元数据继续导入。在模拟器中，直接调用原生 VideoContext.seek 也出现返回首帧的现象；因此不能把模拟器的画面定位当作真机效果验收，也没有记录或宣称真机拖动耗时。Node 测试验证了定位参数、节流、状态和最终 JPEG 的提取时机，不能替代硬件取帧。

本轮未连接真机。仍需在目标微信设备复验：导入后首次拖动、连续来回选封面、短片段两端拖动、生成封面与所选时刻、相册动态播放。用户此前确认的视频生成功能可用，不等于本次交互已经完成真机复验。
